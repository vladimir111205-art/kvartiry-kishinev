# Агент 19: квартиры Кишинёв

Мониторинг рынка квартир Кишинёва для инвестиционных решений. Находит объекты,
**недооценённые относительно рынка**: не «появилась новая двушка», а «двушка в
Ботанике вышла по 1 040 €/м² при медиане сектора 1 380 €/м²».

Получатель один - отец Владимира, канал - Telegram-бот. Больше бот не пишет
никому: алерты о поломках только в логе Actions, о красном прогоне GitHub
присылает письмо владельцу репозитория.
Крутится в GitHub Actions по расписанию, компьютер для этого включать не нужно.

> Это **отдельный публичный репозиторий** (публичный ради безлимитных минут Actions; в git нет ни базы, ни чужих данных, секреты скрыты). Внутри weview
> лежит рабочая копия в `agents/19_kvartiry_kishinev/`, но в git weview она не
> попадает: агент коммитит состояние ежедневно, и бот-коммиты замусорили бы
> историю weview (правила 2 и 7 CLAUDE.md).

План со всеми решениями: `plans/2026-09-17-agent-19-kvartiry-kishinev.md` в weview.

## Как это работает

```
999.md -> нормализация -> запись ВСЕГО в базу -> медианы €/м² по сектор+комнатность
                                              -> события (новое / цена упала / снято)
                                              -> фильтры профиля -> очередь -> Telegram
```

Собираем весь рынок, а фильтруем только на отправке. Иначе не из чего считать
медиану, и агент выродится в ленту новостей вместо оценки «дёшево или нет».

## Как поменять фильтр

Правится **только** `filtry.yaml`, код трогать не нужно.

```yaml
profili:
  - imya: "двушки папе"
    aktiven: true
    poluchatel: papa
    pravila:
      - {pole: cena_eur, op: mezhdu, znachenie: [35000, 90000]}
      - {pole: sektor,   op: v_spiske, znachenie: [botanika, chekany]}
```

**Контракт расширения:** новый фильтр по существующему полю - одна строка в
YAML, ноль правок кода. Новое поле - строка в `normalizacia.py` плюс строка в
словаре источника.

Опечатка в имени поля или оператора **роняет запуск с алертом**, а не молча
пропускает всё подряд. Это нарочно: молчаливый «фильтр-пропускай-всё» опаснее
падения.

Доступные поля карточки: `istochnik, vneshniy_id, url, zagolovok, sdelka, gorod,
sektor, ulica, cena, valyuta, cena_eur, cena_eur_za_m2, komnat, ploshad_m2,
etazh, etazhnost, tip_doma, sostoyanie, prodavec, avtor_login, opisanie, foto,
podnyato_at, otklonenie_ot_rynka`.

Операторы: `ravno, ne_ravno, v_spiske, ne_v_spiske, ne_menshe, ne_bolshe,
mezhdu, soderzhit, ne_soderzhit, est, net, ne_ravno_polyu`.

## Запуск

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/pytest -q                      # тесты, офлайн, без сети
.venv/bin/python run.py --rezhim proba   # прогон на фикстурах, наружу не шлёт
```

В Actions: `obhod.yml` держит цикл 55 минут (верхушка ленты раз в 30 секунд,
весь рынок раз в 5 минут), сохраняет базу в кэш и сам запускает следующее
звено. Цепочка идёт круглосуточно: с 09:00 до 22:00 по Кишинёву шлёт сразу,
ночью только смотрит рынок и копит, всё ночное уходит в 09:00. Расписание
только подхватывает цепочку, если оборвалась. Кнопка `Run workflow`:
`boy` - боевой цикл, `proba` - один прогон на фикстурах.

## Что делать при поломке

| Симптом | Причина | Что делать |
|---|---|---|
| Пришёл алерт «нашли 0 объявлений три прогона подряд» | 999.md сменил схему GraphQL или закрылся от раннера | Снять запрос заново из DevTools в `istochniki/devyat999_zapros.graphql` |
| Красный workflow | падение питона или отвал зависимости | Логи в Actions, шаг `if: failure()` уже прислал алерт |
| Бот молчит неделю, прогоны зелёные | новых объектов правда нет | Раз в неделю бот сам пишет «я на связи» |
| Утром цепочка не проснулась | GitHub выключил cron после 60 дней без активности | Суточная отметка `state/pulse.txt` это сбрасывает; включить workflow в Actions |
| Потерялся кэш Actions | кэш живёт 7 дней без обращений | Холодный старт: бот заново соберёт рынок и пришлёт одну сводку вместо лавины |
